Week 6: from one webcam to a six-person exam room

First group recording (Test_1), seat-based identity, phone-vs-calculator detection, two new events, and a first comparison of all four methods on the whole video.

Research question

Can temporal and contextual analysis improve the reliable detection of predefined exam-room events compared with simple frame-level detection?

Methods compared on identical detections: B0 frame-level (frame), B1 3-second rule (baseline), temporal confirmation + consolidation (improved) and + examination context (context). Alerts are prompts for a human invigilator; the system never decides that a student cheated.

Test_1: the recording

  • Phone camera at the front of a university room, 4 min 31 s, 4K HEVC converted once to 1080p H.264 (no audio).
  • Six participants: three in the front row, three behind; calculators and pencil cases on every desk, real phones used by some participants.
  • Processed on a laptop CPU (no GPU): every 2nd frame (15 per second of video), pose model at 960 px, object detector at 1280 px.

Fewer alerts is not yet “better”: without ground truth these are review-load numbers, not precision or recall. Labelling Test_1 is the next step (tool ready).

The original B1 rule has a multi-person bug that the single-webcam tests hid: one phone produces a “phone on desk” alert for all six students at the same second (e.g. 21.5 s and 27.3 s with the original detector). The improved method assigns each phone to one owner.

Context = improved on Test_1, because this viewpoint has no allowed-look directions configured and calculators are already no longer phones. Context’s effect here is only what it logs instead of alerting (calculators as permitted devices). Showing its value needs a recording with a clock / invigilator side.

Limitations to state honestly

  • No ground truth yet for Test_1: all numbers above are alert counts and eye checks, not precision / recall.
  • Thresholds were adjusted on the same video they are shown on (head yaw 0.12, looking-down rule). They must be frozen and tested on a second recording.
  • Material exchange produces false alerts where rows overlap in the image (one camera, no depth).
  • CPU only: the new detector cannot run at full frame rate live; the demo replays saved detections, the live webcam runs object detection in the background (boxes update about twice a second).
  • One session, six participants, one camera position, one lighting condition.

Questions for the supervisor

  1. Short phone use: should phone_in_hand keep the 3-second rule (F2’s 2-second look is not alerted), or use 1 second like exchanges, since any phone use may matter?
  2. Material exchange: accept the event with its row-overlap false alerts and report them, require a detected sheet of paper, or limit it to neighbours in the same row?
  3. Evaluation design: label Test_1 as the development set and record a second group session (protocol v3) as the held-out test set with frozen thresholds — agreed?
  4. Context: for the next recording, which allowed look directions (clock, invigilator) should the room have, so the context method can be evaluated?
